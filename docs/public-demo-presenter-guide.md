# Five-minute public demonstration

“Atlas shows what is required, why it applies, what evidence supports your position, and what remains unresolved before your team moves forward.”

Primary story: supplier evidence correction. Allow about 45 seconds per step and one minute for the review. Opening Presenter / advanced controls → Presenter walkthrough is read-only.

## 1. ForgeWorks Safety-Related Valve Supplier Review

**Show:** Mission Control → ForgeWorks Safety-Related Valve Supplier Review (project card)

**Say:** “This is a bounded supplier desk review. The starting blocker is a superseded quality program.”

**Expected:** The project Overview shows the blocker and next action.

**Saved progress:** If progress exists, inspect the current state. For a fresh story, use Reset saved demo and confirm; this resets all three browser projects.

## 2. Requirements

**Show:** Requirements → Current quality program document

**Say:** “Revision B conflicts with the expected Revision C. Atlas keeps that conflict visible.”

**Expected:** The requirement card shows Conflict, or the current reviewed state if already corrected.

**Saved progress:** Use Evidence to inspect retained Revision B and its replacement history if corrected.

## 3. Basis for this control

**Show:** Expand Basis for this control under Current quality program document.

**Say:** “This is an Atlas workflow control, not a statutory duty. No NQA-1 edition, contract or license incorporation has been verified.”

**Expected:** The panel displays source category, facts, evidence expectation and review boundary.

**Saved progress:** Opening this panel never changes or resets data.

## 4. Evidence

**Show:** Evidence → select the quality program record; inspect content, version and linked requirement.

**Say:** “The file has an identity and a revision. Attachment alone does not establish that it supports this supplier.”

**Expected:** The retained sample content and supersession metadata can be inspected.

**Saved progress:** If Rev. C is already present, show the retained replacement history and current links.

## 5. Load sample evidence

**Show:** Requirements → Load sample evidence in Current quality program document, then Calibration record sample. Simulated supplier review → Decision explanation → Simulate supplier acceptance.

**Say:** “We replace the represented issue and inspect both records. This explanation records a bounded simulated review; it does not qualify the supplier.”

**Expected:** A current simulated decision records scope and evidence versions. Say: “Rev. C matches the expected sample identity and the calibration sample is linked; broader qualification remains open.”

**Saved progress:** If already accepted, show the saved explanation and History. Avoid creating a duplicate decision just for the presentation.

## 6. Report

**Show:** Report → Download HTML report → Download evidence/action register; optionally Print / save PDF.

**Say:** “The report preserves the finding, authority category, applicability, evidence versions and decision basis. Remaining work travels with the result.”

**Expected:** Downloaded HTML and CSV include supporting legal/basis mapping and the original decision snapshot.

**Saved progress:** Downloads reflect current progress and preserve earlier decisions as history.

## Transportation alternative

Open HALEU UF6 Highway Shipment Readiness → Requirements. Show the concrete package blocker; expand Basis for this control beside the package action and Why is this required? for Material and HRCQ facts. Show the official § 173.403 link and missing activity facts. Say: “The regulation defines HRCQ. This demo selects an assumption and checks sample evidence; it cannot determine actual HRCQ or authorize a shipment.”

Load sample package evidence → Resolve HRCQ facts → Load sample emergency response evidence → Emergency response evidence: Domestic highway supported → Assign demo reviewer. Inspect evidence in Evidence, return to Requirements, then Simulate governed acceptance → Report → Download HTML report / Download evidence/action register. Expected: current simulated acceptance with legal applicability still unresolved. If already saved, show its current or historical decision; if facts differ, restore the represented scope or use the confirmed reset flow. Changing Quantity to 13 makes the package outside scope and invalidates the current decision.

## Application alternative

Open Piketon Advanced Reactor COL Assembly → Requirements / application. Expand Why is this required? on an intake question and show the exact official provision. Say: “This is an application information requirement; the visitor’s answer remains an unverified fact.” Inspect or load the relevant sample, use Save and continue through fourteen questions (Skip for now retains a visible gap), then Finish guided demonstration → Edit answer → Save edit → View your application draft → Download HTML report. Expected: bounded draft with open sections and legal review. There is no application acceptance button. Saved progress resumes; show Edit answer if already complete.

Reset saved demo always uses the existing confirmation and removes all three projects’ progress in this browser. Cancel preserves data. No help action resets data. Use sample/non-sensitive records. Reviews are simulated and browser-local; no NRC acceptance, shipment authorization, full supplier qualification or NQA-1 certification is represented.
